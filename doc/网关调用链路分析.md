# 网关调用链路分析文档

> 版本: 3.6.3 | 日期: 2026-08-03 | 模块: spzx-gateway (端口 8080)

---

## 一、网关定位

`spzx-gateway` 是整个 SPZX 微服务平台的**唯一入口**，基于 **Spring Cloud Gateway**（WebFlux 响应式架构）。所有外部请求（管理后台 + H5 前端）都必须经过网关，它负责：

- 统一鉴权（JWT 验证 + Redis 会话校验）
- 验证码校验
- XSS 脚本清洗
- URL 黑名单拦截
- Sentinel 流量控制
- 请求体缓存（解决流不可重复读问题）
- 路由转发到下游微服务

---

## 二、网关组件总览

### 2.1 过滤器清单

| 顺序 | 过滤器 | 实现类型 | 优先级(Order) | 核心职责 |
|------|--------|----------|---------------|----------|
| 1 | `CacheRequestFilter` | GatewayFilter | — | 缓存 POST/PUT 请求体，解决流不可重复读 |
| 2 | `ValidateCodeFilter` | GatewayFilter | — | 登录/注册时校验图形验证码 |
| 3 | `BlackListUrlFilter` | GatewayFilter | — | 正则匹配拦截黑名单 URL |
| 4 | `XssFilter` | GlobalFilter | **-100** | 清洗 JSON 请求体中的 XSS 脚本 |
| 5 | `AuthFilter` | GlobalFilter | **-200** | JWT 鉴权 + Redis 会话校验 + 注入用户头 |
| 6 | Sentinel 流控 | — | — | 网关级别限流 |
| 7 | 路由转发 | — | — | 将请求转发到下游微服务 |

### 2.2 异常处理器

| 处理器 | 触发条件 | 返回信息 |
|--------|----------|----------|
| `GatewayExceptionHandler` | NotFoundException | "服务未找到" |
| `GatewayExceptionHandler` | ResponseStatusException | 取其 message |
| `GatewayExceptionHandler` | 其他异常 | "内部服务器错误" |
| `SentinelFallbackHandler` | BlockException（限流/降级） | "请求超过最大数，请稍候再试" |

## 三、完整请求链路

```
外部请求 (例: GET /product/brand/list)
  Authorization: Bearer eyJhbGciOiJIUzUxMiJ9...
    │
    ▼
┌───────────────────────────────────────────────────────────────────┐
│                    Spring Cloud Gateway (WebFlux)                   │
│                                                                     │
│  ① CacheRequestFilter                                              │
│     判断请求方法: GET/DELETE → 直接放行 / POST/PUT → 缓存 Body     │
│     │                                                               │
│     ▼                                                               │
│  ② ValidateCodeFilter                                              │
│     判断路径: 非 /auth/login|register → 跳过                        │
│     登录/注册: 从 Body 提取 code+uuid, 校验 Redis 中的验证码        │
│     验证码关闭 (captchaProperties.enabled=false) → 跳过             │
│     校验失败 → 直接返回错误, 链路终止                                │
│     │                                                               │
│     ▼                                                               │
│  ③ BlackListUrlFilter                                              │
│     判断: URL 是否匹配黑名单正则?                                    │
│     命中 → 返回 "请求地址不允许访问", 终止                           │
│     │                                                               │
│     ▼                                                               │
│  ④ XssFilter (order=-100)                                          │
│     判断: XSS 开关关闭? → 跳过                                       │
│     判断: GET/DELETE? → 跳过                                        │
│     判断: Content-Type 非 JSON? → 跳过                              │
│     判断: URL 在排除列表? → 跳过                                     │
│     否则 → EscapeUtil.clean() 清洗 Body, 移除 content-length 头      │
│     │                                                               │
│     ▼                                                               │
│  ⑤ AuthFilter (order=-200)  ★ 核心鉴权 ★                           │
│     ├── Step 1: 白名单检查                                          │
│     │     StringUtils.matches(url, ignoreWhite.whites)              │
│     │     命中 → 跳过鉴权, 直达路由转发                              │
│     │                                                               │
│     ├── Step 2: 提取 JWT                                            │
│     │     从 Authorization 头取值, 去掉 "Bearer " 前缀               │
│     │     为空 → 401 "令牌不能为空"                                  │
│     │                                                               │
│     ├── Step 3: 解析 JWT                                            │
│     │     JwtUtils.parseToken(token) → Claims                       │
│     │     解析失败/过期 → 401 "令牌已过期或验证不正确"               │
│     │     提取: user_id, user_key, username                         │
│     │                                                               │
│     ├── Step 4: 校验 Redis 会话                                      │
│     │     redisService.hasKey("login_tokens:" + user_key)           │
│     │     不存在 → 401 "登录状态已过期"                              │
│     │                                                               │
│     ├── Step 5: 注入用户信息到下游请求头                              │
│     │     header: user_id  = <userId>                               │
│     │     header: username = <username>                             │
│     │     header: user_key = <userKey>                              │
│     │                                                               │
│     └── Step 6: 清除内部来源头                                       │
│           移除 header: from-source                                   │
│           （防止外部请求伪造内部调用，保护 @InnerAuth 接口）          │
│     │                                                               │
│     ▼                                                               │
│  ⑥ Sentinel 网关流控                                                │
│     规则来源: Nacos sentinel-spzx-gateway (gw-flow 类型)             │
│     触发限流 → SentinelFallbackHandler → "请求超过最大数"            │
│     │                                                               │
│     ▼                                                               │
│  ⑦ 路由转发                                                        │
│     根据 Nacos 中的路由配置, 通过 LoadBalancer 转发到目标服务        │
│     例: /product/** → lb://spzx-product:9205                        │
│                                                                     │
└───────────────────────────────────────────────────────────────────┘
    │
    ▼
下游微服务 (如 spzx-product:9205)
  ├── HeaderInterceptor: 提取 user_id/username/user_key → ThreadLocal
  ├── @PreAuthorizeAspect: 校验 @RequiresPermissions/@RequiresRoles
  └── 业务逻辑处理, 返回响应
```

## 四、AuthFilter 详解（网关核心）

### 4.1 源码路径
`spzx-gateway/src/main/java/com/spzx/gateway/filter/AuthFilter.java`

### 4.2 类定义

```java
@Component
public class AuthFilter implements GlobalFilter, Ordered {
    // GlobalFilter: 全局过滤器，对所有路由生效
    // Ordered: 优先级 -200，在 XssFilter(-100) 之后执行
}
```

### 4.3 依赖注入

| 依赖 | 用途 |
|------|------|
| `IgnoreWhiteProperties ignoreWhite` | 白名单 URL 列表，来自 Nacos 配置 `security.ignore.whites` |
| `RedisService redisService` | 校验用户会话是否存在于 Redis |

### 4.4 鉴权流程

```
请求进入 AuthFilter.filter()
        │
        ▼
┌───────────────────┐
│ 1. 获取请求路径     │  url = request.getURI().getPath()
└───────┬───────────┘
        │
        ▼
┌───────────────────┐
│ 2. 白名单匹配       │  StringUtils.matches(url, ignoreWhite.whites)
│   命中? ──YES──→ 放行(chain.filter)
└───────┬───────────┘
        │ NO
        ▼
┌───────────────────┐
│ 3. 提取 JWT 令牌   │  从 Authorization 头取值
│   去掉 "Bearer "   │  为空 → 401 "令牌不能为空"
└───────┬───────────┘
        │
        ▼
┌───────────────────┐
│ 4. 解析 JWT        │  JwtUtils.parseToken(token) → Claims
│   提取声明:         │  {user_id, user_key, username}
│   解析失败 → 401    │  "令牌已过期或验证不正确"
└───────┬───────────┘
        │
        ▼
┌───────────────────┐
│ 5. 校验 Redis 会话  │  redisService.hasKey("login_tokens:" + user_key)
│   不存在 → 401      │  "登录状态已过期"
└───────┬───────────┘
        │
        ▼
┌───────────────────┐
│ 6. 校验声明完整性   │  user_id / username 任意为空 → "令牌验证失败"
└───────┬───────────┘
        │
        ▼
┌───────────────────────────────────────────────┐
│ 7. 注入请求头 + 清除风险头                      │
│   addHeader(mutate, "user_key",  userkey)     │
│   addHeader(mutate, "user_id",   userid)      │
│   addHeader(mutate, "username",  username)    │
│   removeHeader(mutate, "from-source")         │ → 防止伪造内部调用
└───────────────────────────────────────────────┘
        │
        ▼
      放行 → 进入 Sentinel 流控 → 路由转发
```

### 4.5 JWT 令牌格式

```
请求头:
  Authorization: Bearer eyJhbGciOiJIUzUxMiJ9.eyJ1c2VyX2lkIjoxLCJ1c2VyX2tleSI6IjUwMjZmMWU2LWNmY2QtNGE3Ny1iMjg2LTYwZDBlZjVmMTYwNCIsInVzZXJuYW1lIjoiYWRtaW4ifQ.xxx

解析后 Claims:
  {
    "user_id":   1,
    "user_key":  "5026f1e6-cfcd-4a77-b286-60d0ef5f1604",
    "username":  "admin"
  }

Redis 会话键:
  login_tokens:5026f1e6-cfcd-4a77-b286-60d0ef5f1604
```

## 五、各过滤器详细分析

### 5.1 CacheRequestFilter

**实现类:** `AbstractGatewayFilterFactory<Config>`
**源码位置:** `filter/CacheRequestFilter.java`

```
请求入 → 判断方法
  ├── GET / DELETE → 直接放行（这些请求无 Body）
  └── POST / PUT   → ServerWebExchangeUtils.cacheRequestBodyAndRequest()
                      缓存请求体到 exchange 属性中
                      后续过滤器可重复读取 Body（如 ValidateCodeFilter、XssFilter）
```

> **为什么需要？** Spring WebFlux 的请求体是流式的，默认只能读一次。此过滤器将 Body 缓存后，后续的 `ValidateCodeFilter` 和 `XssFilter` 都能重复读取。

### 5.2 ValidateCodeFilter

**实现类:** `AbstractGatewayFilterFactory<Object>`
**源码位置:** `filter/ValidateCodeFilter.java`
**拦截路径:** `/auth/login`、`/auth/register`

```
请求入 → 判断:
  ├── 路径不是 /auth/login 或 /auth/register → 跳过
  ├── captchaProperties.enabled == false     → 跳过
  └── 路径匹配 + 开关开启:
        ├── resolveBodyFromRequest() → 从请求体提取 JSON
        ├── JSON.parseObject(body) → 取出 code 和 uuid
        ├── validateCodeService.checkCaptcha(code, uuid)
        │     从 Redis 中取 captcha_codes:<uuid>
        │     比对 code，并删除 Redis 中的验证码（一次性）
        ├── 匹配成功 → 放行
        └── 匹配失败 → 返回错误信息
```

> **全局开关:** Nacos 配置中 `captchaProperties.enabled` 控制，可在线关闭验证码校验。

### 5.3 BlackListUrlFilter

**实现类:** `AbstractGatewayFilterFactory<Config>`
**源码位置:** `filter/BlackListUrlFilter.java`

```
请求入 → Config.matchBlacklist(url)
  黑名单支持 ** 通配符:
    例: /black/** → Pattern.compile("(.*?)")
  命中 → 返回 "请求地址不允许访问"
  未命中 → 放行
```

> **配置方式:** 黑名单规则通过 Nacos 动态配置，支持热更新。

### 5.4 XssFilter

**实现类:** `GlobalFilter, Ordered`
**源码位置:** `filter/XssFilter.java`
**优先级:** -100
**条件开关:** `@ConditionalOnProperty(value = "security.xss.enabled", havingValue = "true")`

```
请求入 → 逐层判断:
  ├── security.xss.enabled != true  → 跳过
  ├── GET / DELETE                  → 跳过
  ├── Content-Type 非 JSON          → 跳过
  ├── URL 匹配 excludeUrls          → 跳过
  └── 全部不跳过:
        ├── 读取请求体字节
        ├── EscapeUtil.clean(bodyStr)  → 清洗 HTML/JS 脚本标签
        ├── 写回新的字节
        ├── 移除 Content-Length 头
        └── 设置 Transfer-Encoding: chunked
```

> **注意:** XssFilter 需要读取并重写请求体。`CacheRequestFilter` 必须先执行以缓存原始的不可重复读的 Body。

### 5.5 Sentinel 流控

**配置:** `bootstrap.yml`
```yaml
spring:
  cloud:
    sentinel:
      eager: true                    # 取消懒加载
      transport:
        dashboard: 192.168.6.100:8858
      datasource:
        ds1:
          nacos:
            server-addr: 192.168.6.100:8848
            dataId: sentinel-spzx-gateway
            groupId: DEFAULT_GROUP
            data-type: json
            rule-type: gw-flow        # 网关流控规则
```

> 流控规则持久化在 Nacos 中，支持动态更新。触发限流时由 `SentinelFallbackHandler` 统一返回 "请求超过最大数，请稍候再试"。

## 六、过滤器执行顺序（完整列表）

```
Gateway 初始化
    │
    ├── CacheRequestFilter   (GatewayFilter, 路由级)
    ├── ValidateCodeFilter   (GatewayFilter, 路由级, 仅匹配特定路径)
    ├── BlackListUrlFilter   (GatewayFilter, 路由级)
    │
    ├── XssFilter            (GlobalFilter, order=-100, 条件启用)
    ├── AuthFilter           (GlobalFilter, order=-200, 始终生效)
    │
    ├── Sentinel GwFlow      (网关级流控)
    ├── 其他中间件...
    │
    └── 路由转发 (NettyRoutingFilter)
```

> **优先级规则:** 值越小越先执行。`AuthFilter`(-200) 在 `XssFilter`(-100) 之后执行。但 `AuthFilter` 只校验请求头（不读 Body），而 `XssFilter` 需要读 Body，所以这个顺序是合理的——XSS 清洗完 Body 后再做鉴权，鉴权不会修改 Body。

## 七、路由配置

网关的路由规则**不在本地文件中**，而是配置在 Nacos 的共享配置 `application-dev.yml` 中。典型路由格式：

```yaml
spring:
  cloud:
    gateway:
      routes:
        - id: spzx-auth
          uri: lb://spzx-auth
          predicates:
            - Path=/auth/**
        - id: spzx-system
          uri: lb://spzx-system
          predicates:
            - Path=/system/**
        - id: spzx-product
          uri: lb://spzx-product
          predicates:
            - Path=/product/**
        - id: spzx-user
          uri: lb://spzx-user
          predicates:
            - Path=/user/**
        - id: spzx-channel
          uri: lb://spzx-channel
          predicates:
            - Path=/index/**,/item/**,/list/**,/category/**,/brand/**
```

> `lb://` 前缀表示使用 Spring Cloud LoadBalancer 从 Nacos 注册中心获取服务实例列表进行负载均衡。

## 八、异常处理链

```
请求处理过程中抛出异常
    │
    ├── BlockException (Sentinel 限流/降级异常)
    │   └── SentinelFallbackHandler.handle()
    │         → "请求超过最大数，请稍候再试"
    │
    ├── NotFoundException (无可用服务实例)
    │   └── GatewayExceptionHandler.handle()
    │         → "服务未找到"
    │
    ├── ResponseStatusException (HTTP 状态异常)
    │   └── GatewayExceptionHandler.handle()
    │         → ex.getMessage()
    │
    └── 其他 Exception
        └── GatewayExceptionHandler.handle()
              → "内部服务器错误"
```

## 九、关键设计总结

| 设计点 | 说明 |
|--------|------|
| **白名单机制** | 白名单 URL（如 `/auth/login`）跳过鉴权，配置在 Nacos `security.ignore.whites`，支持 `**` 通配 |
| **验证码一次性** | 校验通过后立即删 Redis 中的验证码，防止重复使用 |
| **XSS 条件启用** | 通过 `security.xss.enabled` 开关 + `excludeUrls` 排除列表灵活控制 |
| **from-source 防护** | 网关清除外部请求的 `from-source` 头，下游 `@InnerAuth` 切面强制要求该头 = "inner"，确保内部端点无法被外部直接调用 |
| **JWT + Redis 双重验证** | JWT 携带用户标识，Redis 存储会话状态。网关两者都校验——JWT 过期或 Redis 会话不存在都返回 401 |
| **请求体缓存** | `CacheRequestFilter` 解决 WebFlux 流不可重复读的问题，`ValidateCodeFilter` 和 `XssFilter` 都依赖它 |
| **响应式全链路** | 所有过滤器和异常处理都基于 WebFlux 响应式编程（`Mono<Void>`），非阻塞 I/O，高吞吐 |
