```
│              下游微服务 (spzx-system/product/user/order...)             │
│                                                                       │
│  Servlet Filter:   TraceIdFilter (透传 traceId)                        │
│  MVC Interceptor:  HeaderInterceptor  ★ 用户上下文绑定 ThreadLocal     │

```

**一句话总结**：一个前端请求从发出到执行业务逻辑，依次经过 **axios 拦截器 → Nginx → 网关 6 类过滤器 → 下游服务拦截器/AOP 切面** 共约 10 层前置处理，其中 5 层与安全认证相关。

## 二、前端层（Vue3 + Axios）前置处理

### 2.1 axios 请求拦截器（`spzx-ui/src/utils/request.js`）

| 功能 | 说明 |
|------|------|
| **Token 注入** | 从 Cookie（`Admin-Token`）读取 token，自动附加 `Authorization: Bearer <token>` 头；`isToken: false` 的请求（如登录、验证码）除外 |
| **GET 参数序列化** | 将 `params` 对象转换为 query string 拼接到 URL |
| **防重复提交** | POST/PUT 请求，在 sessionStorage 中记录 url+data+time；1 秒内相同请求视为重复提交直接拒绝（数据量 > 5M 跳过校验） |
| **响应统一处理** | `code===401` → 弹出"重新登录"确认框，调 `logOut()` 清 Cookie 跳转登录页；`code===500` 弹错误；`code===601` 弹警告；`code!==200` 弹 Notification |
| **网络异常兜底** | Network Error → "后端接口连接异常"；timeout → "系统接口请求超时"；HTTP 状态码异常 → "系统接口 xxx 异常" |

### 2.2 Token 存储（`spzx-ui/src/utils/auth.js`）

- 登录成功后 token 存 Cookie（`Admin-Token`），`expires_in` 存 `Admin-Expires-In`
- 使用 Cookie 而非 localStorage，保证跨标签页同步 + 页面刷新不丢失

### 2.3 路由守卫 / 权限指令（`spzx-ui/src/plugins/auth.js`、`permission.js`）

- 前端路由守卫在进入页面前校验 `getToken()`，未登录跳转 `/login`
- 按钮级权限通过 `v-hasPermi` / `v-hasRole` 自定义指令控制（**仅做 UI 隐藏，真正拦截在后端**）

### 2.4 登录页（`spzx-ui/src/views/login.vue`）

1. 加载页面时请求 `GET /code` 获取图形验证码（Base64 图片 + uuid）
2. 提交 `{username, password, code, uuid}` 到 `/auth/login`
3. 记住密码功能用 `jsencrypt` 前端加密后存 Cookie

## 三、Nginx 反向代理层

`docker/nginx/conf/nginx.conf`

| 配置 | 作用 |
|------|------|
| `location /` | 托管 Vue 静态资源，`try_files` 实现 SPA history 路由回退到 index.html |
| `location /prod-api/` | 反向代理到 `http://spzx-gateway:8080/`，附带 `X-Real-IP`、`X-Forwarded-For` 等真实 IP 头（网关/IP黑名单功能依赖） |
| `if ($request_uri ~ "/actuator")` | 返回 403，**防止 Spring Boot Actuator 监控端点暴露** |

## 四、网关层（Spring Cloud Gateway）前置处理

网关是唯一外部入口（8080），基于 WebFlux 响应式架构。全部过滤器按执行顺序：

### 4.1 TraceIdFilter（GlobalFilter, order=-300，最先执行）

- 为每个请求生成 `UUID` 形式的 `traceId`，注入请求头 `X-Trace-Id`，同时写入 MDC
- 作用：全链路日志追踪（网关 → 下游 → Feign 调用），配合 SkyWalking 定位问题
- `doFinally(MDC.clear())` 保证 MDC 不泄漏到其他请求

### 4.2 CacheRequestFilter（GatewayFilter，路由级）

- 仅对 POST/PUT 缓存请求体（`ServerWebExchangeUtils.cacheRequestBodyAndRequest`）
- **作用**：WebFlux 请求体是流式的只能读一次，缓存后 `ValidateCodeFilter`、`XssFilter` 才能重复读取 Body

### 4.3 ValidateCodeFilter（GatewayFilter，路由级）

- 仅拦截 `/auth/login`、`/auth/register` 两个路径，且受 `captchaProperties.enabled` 全局开关控制
- 从缓存 Body 解析 JSON，取 `code` + `uuid`，调 `validateCodeService.checkCaptcha()` 与 Redis 中 `captcha_codes:<uuid>` 比对
- **一次性验证码**：校验通过后立即删除 Redis 中的验证码，防止重放
- 失败直接返回响应，链路终止

### 4.4 BlackListUrlFilter（GatewayFilter，路由级）

- 黑名单 URL 正则匹配（支持 `**` 通配符 → `(.*?)`），命中返回 "请求地址不允许访问"
- 规则通过 Nacos 动态配置，支持热更新（`@RefreshScope`）

### 4.5 XssFilter（GlobalFilter, order=-100，条件启用）

- `@ConditionalOnProperty(security.xss.enabled=true)` 才注册；内部再次判断开关
- 跳过条件：GET/DELETE、非 JSON Content-Type、命中 `excludeUrls`
- 处理逻辑：读 Body → `EscapeUtil.clean()` 清洗 HTML/JS 脚本 → 写回 → 删除 Content-Length、改 chunked 编码

### 4.6 AuthFilter（GlobalFilter, order=-200，★ 核心鉴权）

鉴权五步：

```
① 白名单判断   StringUtils.matches(url, ignoreWhite.whites)  → 命中直接放行
② 提取 Token   Authorization 头去掉 "Bearer " 前缀，为空 → 401 "令牌不能为空"
③ 解析 JWT     JwtUtils.parseToken() → Claims {user_id, user_key, username}
               解析失败/过期 → 401 "令牌已过期或验证不正确"
④ Redis 会话   校验 login_tokens:<user_key> 是否存在 → 不存在 → 401 "登录状态已过期"
⑤ 注入请求头   向下游传递 user_key / user_id / username（URL 编码）
   安全清理     removeHeader("from-source") —— 防止外部伪造内部调用
```

**设计要点**：
- **JWT + Redis 双重校验**：JWT 保证令牌本身可信（HS512 签名），Redis 保证会话真实存在（支持注销/踢人）
- **白名单热刷新**：`IgnoreWhiteProperties` 带 `@RefreshScope`，Nacos 修改 `security.ignore.whites` 即时生效
- **防伪造**：外部请求即使带上 `from-source: inner` 头也会被网关剥离，保护下游 `@InnerAuth` 接口

### 4.7 Sentinel 网关流控

- 规则持久化于 Nacos（dataId `sentinel-spzx-gateway`，gw-flow 类型），支持动态更新
- 触发限流 → `SentinelFallbackHandler` → "请求超过最大数，请稍候再试"

### 4.8 网关异常处理

| 处理器 | 触发条件 | 返回 |
|--------|----------|------|
| `GatewayExceptionHandler` | NotFoundException | "服务未找到" |
| `GatewayExceptionHandler` | ResponseStatusException | 异常 message |
| `GatewayExceptionHandler` | 其他 | "内部服务器错误" |
| `SentinelFallbackHandler` | BlockException | "请求超过最大数，请稍候再试" |

### 4.9 辅助端点（路由函数）

- `GET /code`（RouterFunction，WebFlux 函数式路由）→ `ValidateCodeHandler` → 生成图形验证码（kaptcha 字符/数学两种模式），Base64 返回 `{uuid, img, captchaEnabled}`

## 五、下游微服务层前置处理

请求到达业务服务后，还有 4 层切面/拦截器处理（由 `@EnableCustomConfig` 复合注解自动装配）：

### 5.1 HeaderInterceptor（Spring MVC 拦截器，order=-10）

`spzx-common-security/interceptor/HeaderInterceptor.java`

```
preHandle:
  ① 非 HandlerMethod（静态资源）直接放行
  ② 从网关注入的请求头提取 user_id/username/user_key → SecurityContextHolder (TransmittableThreadLocal)
  ③ 若有 token → AuthUtil.getLoginUser(token) 从 Redis 取 LoginUser
  ④ 会话剩余有效期 < 2 小时 → 自动续期（refreshToken）
afterCompletion:
  SecurityContextHolder.remove()  ← 防止 ThreadLocal 内存泄漏
```

**关键点**：
- 使用 `TransmittableThreadLocal`（阿里 TTL），可跨异步线程/线程池传递用户上下文
- **不信任请求头本身，只信任网关**——下游服务从不在请求头读取敏感信息，而是用 `user_key` 去 Redis 取权威会话数据

### 5.2 PreAuthorizeAspect（Spring AOP 注解鉴权）

- 切点：`@RequiresLogin` / `@RequiresPermissions` / `@RequiresRoles`
- `@Around` 环绕：先校验后放行，校验失败抛 `NotPermissionException` / `NotRoleException` / `NotLoginException`，由 `GlobalExceptionHandler` 统一转成 403/401 响应
- 逻辑实现：`AuthLogic`（仿 Sa-Token 设计）
  - 权限/角色集合从 `LoginUser`（Redis 缓存）中获取，不查库
  - 支持 `Logical.AND` / `Logical.OR` 多值逻辑
  - 通配符匹配 `PatternMatchUtils.simpleMatch`（如 `system:user:*`）
  - 超级权限 `*:*:*` 和超级角色 `admin` 直接放行

### 5.3 InnerAuthAspect（内部调用保护）

- `@Around("@annotation(innerAuth)")`，order 为 `HIGHEST_PRECEDENCE+1`（先于权限切面执行）
- 校验请求头 `from-source == "inner"`，否则抛 `InnerAuthException`
- `innerAuth.isUser()` 为 true 时还需校验 user_id/username 头非空
- **安全模型**：网关会剥离外部请求的 `from-source` 头 → 外部永远无法访问 `@InnerAuth` 接口 → 只有通过 Feign（`FeignRequestInterceptor` 自动附加该头）的内部调用才能访问

### 5.4 FeignRequestInterceptor（服务间调用上下文传递）

- 服务间 Feign 调用时自动透传：`user_id`、`user_key`、`username`、`Authorization`、`X-Trace-Id`
- 附加 `X-Forwarded-For`（客户端真实 IP）
- 同时由 Feign 调用方代码显式传入 `from-source: inner` 头（如 `remoteUserService.getUserInfo(username, SecurityConstants.INNER)`）

### 5.5 其他 AOP 前置处理

| 切面 | 注解 | 作用 |
|------|------|------|
| `LogAspect` | `@Log` | 操作日志：记录模块、方法、参数、IP、耗时、状态，异步落库（`AsyncLogService`），敏感字段脱敏（`PropertyPreExcludeFilter`） |
| `GuiguCacheAspect` | `@GuiguCache` | 方法级 Redis 缓存（key 含前缀+方法签名+参数），空值不缓存、可指定过期时间 |
| `GlobalExceptionHandler` | — | 统一异常 → `R<T>` 响应格式，业务异常 500 / 权限异常 403 / 未登录 401 |

## 六、权限认证模块分析

### 6.1 认证体系总览（JWT + Redis 双会话）

```
┌───────────────────────────────────────────────────────────────────┐
│  spzx-auth (9200) 认证中心                                         │
│                                                                    │
│  TokenController   → /login /logout /refresh /register  (管理端)   │
│  H5TokenController → /h5/login /h5/logout /h5/register (H5端)     │
│                                                                    │
│  登录成功 → LoginUser 对象                                          │
│    ① 生成 UUID 作为 user_key（会话唯一标识）                        │
│    ② 将 LoginUser(含权限/角色集合) 缓存 Redis 12 小时               │
│       key: login_tokens:<uuid>                                     │
│    ③ 签发 JWT（HS512，载荷仅含 user_key/user_id/username，无敏感）  │
│    ④ 返回 {access_token, expires_in}                               │
│                                                                    │
│  后续请求 → 网关 AuthFilter 解析 JWT + 校验 Redis → 注入请求头      │
│            → 下游 HeaderInterceptor 绑定上下文 + 会话续期           │
└───────────────────────────────────────────────────────────────────┘
```

**为什么 JWT 之外还要 Redis？**
- JWT 无状态不可吊销，Redis 会话可支持：注销立即失效、强制踢人、会话续期、权限变更即时生效（权限集合存 Redis 而非写进 JWT）

### 6.2 管理端登录实现

**链路**：`POST /auth/login`（网关白名单放行 + 图形验证码校验）→ `TokenController.login` → `SysLoginService.login` → Feign 调 `spzx-system` → 签发 token

`SysLoginService.login()` 校验步骤：

```
① 参数校验        用户名/密码非空、密码 5~20 位、用户名 2~20 位
② IP 黑名单       Redis 中 sys.login.blackIPList 正则匹配当前 IP
③ 查用户信息       Feign → spzx-system /user/info/{username}（@InnerAuth）
                   ↓ 返回 LoginUser（含 SysUser、roles、permissions 集合）
④ 账号状态        删除账号(delFlag) → "账号已被删除"
                  停用(status=1)   → "用户已停用，请联系管理员"
⑤ 密码校验        见 6.6 密码策略（BCrypt + 错误次数锁定）
⑥ 记录日志        Feign → spzx-system 记录登录成功/失败日志
⑦ 签发令牌        TokenService.createToken() 返回 {access_token, expires_in}
```

`spzx-system` 侧 `SysUserController.info()`（@InnerAuth）：查 `SysUser` → `getRolePermission()` 角色集合 → `getMenuPermission()` 权限集合（菜单表 `perms` 字段）→ 组装 `LoginUser` 返回。

### 6.3 H5 端登录实现

**链路**：`POST /h5/login` → `H5TokenController.login` → `H5LoginService.login` → Feign 调 `spzx-user`

与管理端差异：

| 维度 | 管理端 (spzx-system) | H5 端 (spzx-user) |
|------|---------------------|-------------------|
| 用户表 | `sys_user` | `user_info` |
| 用户名规则 | 2~20 位 | 11 位手机号 |
| 权限/角色 | 有（RBAC 菜单权限） | 无（仅普通会员） |
| 登录后动作 | 直接签发 | 额外调 `updateUserLogin` 更新最近登录 IP/时间 |
| 会话内容 | LoginUser + sysUser + roles + permissions | LoginUser（userid/username/password/status） |

### 6.4 注册功能实现

#### 管理端注册（`POST /auth/register`）

```
① 参数校验        用户名 2~20 位、密码 5~20 位
② 组装 SysUser    password = BCrypt 加密
③ Feign 调 spzx-system /user/register（@InnerAuth）
   后端再次校验:
     - 配置开关 sys.account.registerUser != true → "当前系统没有开启注册功能"
     - checkUserNameUnique 用户名唯一
   成功 → userService.registerUser()
④ 记录注册日志
```

#### H5 注册（`POST /h5/register`）—— 手机号 + 短信验证码

```
① 参数校验        用户名必须 11 位（手机号）、密码 5~20 位、验证码必填
② 短信验证码校验   redisTemplate.get("phone:code:" + 手机号) 与提交 code 比对
                  （验证码由 spzx-user /sms/sendCode/{phone} 生成，
                    4 位随机数，存 Redis 5 分钟有效，可替换为真实短信服务）
③ 组装 UserInfo   password = BCrypt 加密
④ Feign 调 spzx-user /userInfo/register（@InnerAuth）→ 唯一性校验 → 入库
⑤ 记录注册日志
```

### 6.5 注销 / 刷新实现

| 端点 | 逻辑 |
|------|------|
| `DELETE /auth/logout` | 取 token → `AuthUtil.logoutByToken(token)` 删 Redis 会话（**立即失效**）→ 记录退出日志 |
| `DELETE /h5/logout` | 同上（不记日志） |
| `POST /auth/refresh` | `tokenService.getLoginUser(request)` 从 Redis 取会话 → `refreshToken` 刷新有效期 → 实现无感续期 |

### 6.6 密码安全策略（SysPasswordService）

```
密码校验:
  ① 从 Redis 取 pwd_err_cnt:<username> 错误次数
  ② 次数 >= 5 → "密码输入错误5次，帐户锁定10分钟"（拒绝校验）
  ③ BCrypt matches 比对:
       失败 → 错误次数+1，写 Redis（TTL 10 分钟），提示"用户不存在/密码错误"
       成功 → 清除错误次数缓存
```

| 配置项 | 值 | 来源 |
|--------|-----|------|
| 最大重试次数 | 5 | `CacheConstants.PASSWORD_MAX_RETRY_COUNT` |
| 锁定时间 | 10 分钟 | `CacheConstants.PASSWORD_LOCK_TIME` |
| 加密算法 | BCrypt（`BCryptPasswordEncoder`） | 不可逆、自带盐，同一密码两次加密结果不同 |

> 注：登录失败的提示统一为"用户不存在/密码错误"，避免用户名枚举攻击。

### 6.7 验证码体系

#### 图形验证码（管理端登录/注册）

| 环节 | 实现 |
|------|------|
| 生成 | 网关 `GET /code` → kaptcha 生成（`char` 字符 / `math` 数学运算两种模式，Nacos 可配）→ Base64 返回 `{uuid, img}` → 明文 code 存 Redis `captcha_codes:<uuid>`（2 分钟） |
| 校验 | 网关 `ValidateCodeFilter` 拦截 `/auth/login` `/auth/register` → 比对后**立即删除**（一次性） |
| 开关 | `captchaProperties.enabled`（Nacos 动态控制，可临时关闭） |

#### 短信验证码（H5 注册）

- `spzx-user GET /sms/sendCode/{phone}` → 生成 4 位随机码 → 存 Redis `phone:code:<phone>`（5 分钟）→ 调用短信服务商发送（模板 id 可配）
- H5 注册时比对 Redis 中的验证码

### 6.8 RBAC 注解鉴权（AOP）

**权限模型**：`sys_user` ↔ `sys_user_role` ↔ `sys_role` ↔ `sys_role_menu` ↔ `sys_menu(perms)`

| 注解 | 校验内容 | 示例 |
|------|----------|------|
| `@RequiresLogin` | 是否已登录（Redis 会话存在） | 通用 |
| `@RequiresPermissions` | 权限标识，支持 `Logical.AND/OR` | `@RequiresPermissions("system:user:list")` |
| `@RequiresRoles` | 角色标识，支持 `Logical.AND/OR` | `@RequiresRoles("admin")` |

执行链：`PreAuthorizeAspect`（AOP）→ `AuthUtil` → `AuthLogic`：

```
① getPermiList()/getRoleList() 从 SecurityContextHolder 中的 LoginUser（Redis 缓存）取集合
   （登录时已由 spzx-system 组装，鉴权零 DB 查询）
② hasPermi: 集合中含 "*:*:*" 或 PatternMatchUtils.simpleMatch(权限, 注解值) → 通过
③ hasRole:  集合中含 "admin" 或 simpleMatch(角色, 注解值) → 通过
④ AND 逻辑：全部满足；OR 逻辑：任一满足，否则抛 NotPermissionException/NotRoleException
```

### 6.9 内部调用保护（@InnerAuth）

```
外部请求: 网关 AuthFilter 强制 removeHeader("from-source") → 无法携带 inner
内部调用: Feign 调用方显式传 @RequestHeader(FROM_SOURCE)="inner"
          + FeignRequestInterceptor 透传用户上下文
服务端:   InnerAuthAspect 校验 from-source=="inner"，isUser=true 还需 user_id/username 非空
```

被保护端点示例：`spzx-system /user/info/{username}`、`/user/register`、`spzx-user /userInfo/register`、`/userInfo/info` 等 —— 均为 Feign 专用，外部不可达。

### 6.10 会话续期机制

```
登录:   LoginUser 缓存 Redis，expireTime = now + 720 分钟（12 小时）
请求:   下游 HeaderInterceptor → verifyToken
        若 expireTime - now <= 120 分钟 → refreshToken 重置 12 小时
效果:   活跃用户会话永不失效（滑动过期），非活跃用户 12 小时后需重新登录
```

## 八、安全设计总结

| 设计点 | 实现 | 防护目标 |
|--------|------|----------|
| **JWT + Redis 双会话** | JWT(HS512) 存标识，Redis 存会话 | 令牌可吊销、可踢人、权限变更即时生效 |
| **网关统一鉴权** | AuthFilter 全局过滤，白名单可热刷新 | 下游服务零鉴权代码，统一入口 |
| **from-source 剥离** | 网关删除外部请求该头 + @InnerAuth 切面校验 | 防止内部 Feign 接口被外部直接调用 |
| **密码 BCrypt + 锁定** | 不可逆加密 + 5 次错误锁 10 分钟 | 防暴力破解、防拖库后撞库 |
| **错误信息模糊化** | 统一"用户不存在/密码错误" | 防用户名枚举 |
| **验证码一次性** | 校验后即删 Redis 中的验证码 | 防验证码重放 |
| **图形验证码开关** | Nacos 动态控制 enabled | 测试环境可关、生产可开 |
| **IP 黑名单** | Redis 存正则列表 + 登录时校验 | 封禁恶意 IP |
| **XSS 清洗** | EscapeUtil.clean + excludeUrls 白名单 | 防存储型/反射型 XSS |
| **URL 黑名单** | Nacos 动态正则 | 封禁敏感路径 |
| **操作日志** | @Log AOP 异步落库 + 敏感字段过滤 | 审计追踪 |
| **全链路 traceId** | 网关生成 → 下游透传 → Feign 透传 | 分布式日志串联、问题定位 |
| **Sentinel 流控** | Nacos 持久化 gw-flow 规则 | 防突发流量打垮服务 |
| **/actuator 拦截** | Nginx 层 403 | 防监控端点泄露 |
| **前端防重复提交** | 1s 内同 url+data 拦截 | 防误触/双击重复下单 |
| **ThreadLocal 清理** | afterCompletion remove + TTL | 防内存泄漏、异步线程上下文传递 |
