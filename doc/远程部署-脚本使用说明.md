# spzx 远程部署脚本使用说明

脚本位置：`docker/remote-deploy.sh`（bash，可在 macOS / Linux 运行）
**所有命令都在仓库根目录执行**，例如 `./docker/remote-deploy.sh all ui`。

一句话原理：**本机打包 → 上传产物 → 服务器上 docker build → docker compose 启动 → 自动验证**。本机不需要装 Docker。

---

## 0. 一分钟上手

```bash
chmod +x docker/remote-deploy.sh        # 首次执行需要加可执行权限

./docker/remote-deploy.sh status                    # 看现状（只读，随便跑）
./docker/remote-deploy.sh all ui                    # 只部署前端
./docker/remote-deploy.sh all auth                  # 只发布认证中心
./docker/remote-deploy.sh                           # 不带参数 = 全部服务走一遍全流程
```

部署完成后入口：

| 入口 | 地址 |
|---|---|
| 前端管理后台 | `http://<服务器IP>/` |
| 网关 API | `http://<服务器IP>:19080/`（`/auth/**`、`/system/**`、`/product/**`…） |

## 1. 前置条件

**本机**：JDK 21、Maven 3.9、Node/npm（只发前端时需要）、`ssh` + `scp`（或 `rsync`）

**服务器**：
- Docker + Docker Compose v2
- 已运行 Nacos / MySQL / Redis（本项目 150.158.27.19 上由 1Panel 提供）
- SSH 免密登录（脚本用 `BatchMode`，无法交互输密码）：
  ```bash
  ssh-copy-id root@<服务器IP>      # 一次性配置
  ssh root@<服务器IP> docker ps    # 验证免密可用
  ```
- Nacos 里**已有** `application-dev.yml` 和各 `spzx-<服务>-dev.yml`，其中的 MySQL/Redis/RabbitMQ 地址指向该服务器自己的基础设施（脚本只打包部署，不生成/不修改这些配置）

## 2. 命令速查表

| 命令 | 作用 | 会不会动服务器 |
|---|---|---|
| `all`（默认） | 对选中服务执行 build → pack → image → up → verify | ✅ 全流程 |
| `build` | 本地打包：后端 `mvn package`（含依赖模块，跳过测试）、前端 `npm run build:prod` | ❌ 只在本机跑 |
| `pack` | 上传产物 + 生成 `Dockerfile` / `nginx.conf` / `docker-compose.yml` 到服务器 | 只写文件 |
| `image` | 服务器上 `docker compose build` | 只建镜像 |
| `up` | 服务器上 `docker compose up -d` | 启动/重建容器 |
| `restart` | `docker compose restart` | 重启容器 |
| `stop` | `docker compose stop` | 停止容器 |
| `down` | 不指定服务=`down`（删除全部）；指定服务=`rm -sf` | 删除容器 |
| `status` | 容器状态 + Nacos 注册状态 + 各容器内存占用 | ❌ 只读 |
| `logs <svc> [-f]` | 看日志，`-f` 持续跟随 | ❌ 只读 |
| `verify` | 验证：注册状态、外网接口、前端反代、完整登录链路 | ❌ 只读 |
| `clean` | 清理服务器上悬空镜像 | 清镜像 |
| `help` | 打印脚本内置帮助 | ❌ |

**服务名**：`gateway` | `auth` | `system` | `product` | `ui`

## 3. 典型场景（可直接复制）

### 3.1 首次全量部署（4 个服务 + 前端）

```bash
./docker/remote-deploy.sh all gateway auth system ui
```
顺序：本地打包 → 上传 → 服务器建镜像 → 启动 → 自动验证。首次会拉取基础镜像 `eclipse-temurin:21-jre`，耗时较长。

### 3.2 只部署前端

```bash
./docker/remote-deploy.sh all ui
```
只构建 `spzx-ui/dist`（约 6 秒、4.8MB），上传压缩包，用 `nginx:alpine` 起一个容器。**注意**：前端占用 80 端口，如果网关当前占着 80，请一起重建（见 7.1）。

### 3.3 只部署某个后端服务

```bash
./docker/remote-deploy.sh all auth          # 只发认证中心
./docker/remote-deploy.sh all system        # 只发系统模块
./docker/remote-deploy.sh all product       # 只发商品服务（需 RabbitMQ，见 7.7）
ONLY="auth system" ./docker/remote-deploy.sh all   # 一次发两个
```
只 `build/pack/image/up` 你选中的服务，**其他容器不会被重建**。远程 compose 文件始终包含全部 5 个服务，所以你随时可以只 up 某一个。

### 3.4 改完代码重新发布某个服务

```bash
./docker/remote-deploy.sh all auth
```
等价于分步：
```bash
./docker/remote-deploy.sh build auth        # mvn 打包
./docker/remote-deploy.sh pack  auth        # 上传 jar（91~108MB，视模块而定）
./docker/remote-deploy.sh image auth        # 服务器 build 镜像
./docker/remote-deploy.sh up    auth        # 重建容器（约 20~40 秒）
./docker/remote-deploy.sh verify gateway    # 顺手验证
```

> 只想重传 **jar**、不想重新编译？`SKIP_MAVEN=1 ./docker/remote-deploy.sh pack auth`（用 `target/` 下已有 jar，会预检 jar 里的 Nacos 地址是否与 `NACOS_ADDR` 一致）。

### 3.5 只调内存参数，不重传 jar（服务器内存紧张时最常用）

```bash
SKIP_JARS=1 SYSTEM_HEAP=256m AUTH_HEAP=160m ./docker/remote-deploy.sh pack auth system
./docker/remote-deploy.sh image auth system
./docker/remote-deploy.sh up auth system
```
`SKIP_JARS=1` 只刷新 `Dockerfile` + `docker-compose.yml`（沿用服务器上已有 jar/前端包），所以调堆大小、端口、cgroup 上限这类参数**不用再传 90MB**。

### 3.6 日常运维

```bash
./docker/remote-deploy.sh status                 # 容器 + Nacos 注册 + 内存占用
./docker/remote-deploy.sh logs gateway           # 最近 200 行
./docker/remote-deploy.sh logs auth -f           # 实时跟随（Ctrl+C 退出）
./docker/remote-deploy.sh restart ui             # 只重启前端
./docker/remote-deploy.sh stop system            # 停掉系统模块（省内存）
./docker/remote-deploy.sh down ui                # 删除前端容器（compose 仍保留定义）
./docker/remote-deploy.sh clean                  # 清理 build 产生的悬空镜像
```

### 3.7 分步执行（想逐步确认时）

```bash
./docker/remote-deploy.sh build ui
./docker/remote-deploy.sh pack  ui
./docker/remote-deploy.sh image ui
./docker/remote-deploy.sh up    ui
./docker/remote-deploy.sh verify ui
```
每步都能单独重跑；`pack` 重复执行是幂等的（会覆盖同名文件）。

### 3.8 版本化发布

```bash
TAG=v1.0.0 ./docker/remote-deploy.sh all gateway auth system
./docker/remote-deploy.sh status           # 查看镜像标签
```
默认 `TAG=latest`（同标签重建会覆盖旧镜像）。

### 3.9 验证的三种粒度

```bash
./docker/remote-deploy.sh verify                     # 全部服务
./docker/remote-deploy.sh verify gateway ui          # 只验网关和前端
REDIS_CONTAINER=1Panel-redis-xmqE REDIS_PASSWORD=940101zx \
  ./docker/remote-deploy.sh verify                   # 额外跑"完整登录链路"
```
`verify` 包含：

| 步骤 | 内容 |
|---|---|
| ① | 轮询等待选中服务在 Nacos 注册（前端跳过，不需要注册） |
| ② | 容器状态 |
| ③ | 外网 `DELETE /auth/logout` → 期望 `code=200`（网关→auth 通） |
| ④ | 外网 `POST /auth/login`（不带验证码）→ 期望返回"验证码不能为空"（验证码过滤器生效） |
| ⑤ | 服务器内 `GET /user/info/admin`（带 `from-source: inner`）→ 期望返回用户信息（DB/Redis 通） |
| ⑥ | 外网 `GET /` 与 `GET /prod-api/auth/logout`（前端 nginx 托管 + 反代网关） |
| ⑦ | 完整登录：往 Redis 写验证码 → 登录 → 校验返回 `access_token`（**需 REDIS_PASSWORD**） |

要验 product 时，`⑦` 会顺带带 token 调 `GET /product/brand/list`。

### 3.10 换一台服务器部署

```bash
SSH_HOST=root@10.0.0.9 \
HOST_IP=10.0.0.9 \
NACOS_ADDR=10.0.0.9:8848 \
NACOS_API=http://127.0.0.1:8848 \
./docker/remote-deploy.sh all gateway auth system ui
```
- `NACOS_ADDR` 会通过 `-Dnacos.addr` **打进 jar**，所以**必须重新 build**（不能配 `SKIP_MAVEN=1`）
- `HOST_IP` 只是外网验证用，默认从 `SSH_HOST` 推导；走跳板机时显式指定
- `NACOS_API` 是脚本查注册状态用的地址（默认在目标机上 curl `127.0.0.1:8848`）
- 换机前确认目标机 Nacos 里已有那几份 `*-dev.yml` 配置，且指向目标机自己的 MySQL/Redis

也可以放到环境文件里复用：
```bash
cat > .deploy.env <<'EOF'
SSH_HOST=root@10.0.0.9
HOST_IP=10.0.0.9
NACOS_ADDR=10.0.0.9:8848
EOF
env $(grep -v '^#' .deploy.env) ./docker/remote-deploy.sh all
```

## 4. 环境变量总表

### 目标机 / 路径

| 变量 | 默认值 | 说明 |
|---|---|---|
| `SSH_HOST` | `root@150.158.27.19` | SSH 目标 |
| `SSH_PORT` | `22` | SSH 端口 |
| `REMOTE_DIR` | `/opt/spzx` | 服务器部署根目录 |
| `HOST_IP` | 从 `SSH_HOST` 推导 | 外网验证用的 IP |
| `TAG` | `latest` | 镜像标签 |
| `IMAGE_PREFIX` | `spzx` | 镜像名前缀（`spzx/spzx-gateway:latest`） |
| `XFER` | `auto` | 传输方式：`auto`/`scp`/`rsync`（服务器上没 rsync 时自动退回 scp） |

### 端口

| 变量 | 默认值 | 说明 |
|---|---|---|
| `GATEWAY_PUBLISH` | `19080:8080` | 网关对外端口（空格分隔可多个） |
| `UI_PUBLISH` | `80:80` | 前端对外端口 |
| `INTERNAL_BIND` | `127.0.0.1` | auth/system 绑定地址（默认只绑回环，不对外裸露） |

### 服务选择 / 跳过

| 变量 | 说明 |
|---|---|
| `ONLY="auth ui"` | 只处理指定服务（也可用位置参数：`... all auth ui`） |
| `SKIP_MAVEN=1` | 跳过后端 Maven 打包（用 `target/` 里已有 jar） |
| `SKIP_JARS=1` | 跳过产物上传，只刷新 Dockerfile/compose |
| `SKIP_UI_BUILD=1` | 跳过前端构建 |
| `UI_BUILD_CMD` | 前端构建命令，默认 `build:prod` |
| `UI_DIR` | 前端目录，默认 `spzx-ui` |

### Nacos / Sentinel

| 变量 | 默认值 | 说明 |
|---|---|---|
| `NACOS_ADDR` | `150.158.27.19:8848` | 打包时 `-Dnacos.addr` 写进 jar（同时用于上传前预检） |
| `NACOS_API` | `http://127.0.0.1:8848` | 脚本查注册状态的地址 |
| `SENTINEL_DASHBOARD` | 空 | 打包时 `-Dsentinel.dashboard`，留空用 pom 默认值 |

### 内存（服务器内存紧张时的重点）

| 变量 | 默认值 | 说明 |
|---|---|---|
| `GATEWAY_HEAP` / `AUTH_HEAP` / `SYSTEM_HEAP` / `PRODUCT_HEAP` | `192m` / `192m` / `320m` / `384m` | 各 JVM `-Xmx` |
| `GATEWAY_MEM` / `AUTH_MEM` / `SYSTEM_MEM` / `PRODUCT_MEM` | 空 | 可选 cgroup 硬上限（设了可防止它拖死别人） |
| `UI_MEM` | `64m` | 前端 nginx 硬上限（实测只用 4~5MB） |
| `JVM_OPTS_EXTRA` | 空 | 追加到 `JAVA_OPTS` 末尾 |
| `CDS` | `1` | 启用类数据共享 `-XX:+AutoCreateSharedArchive`（降低启动时间与元数据内存） |
| `CDS_DIR` | `$REMOTE_DIR/deploy/cds` | CDS 归档在宿主机的目录 |

### verify 第⑦步（完整登录链路）

| 变量 | 默认值 | 说明 |
|---|---|---|
| `REDIS_PASSWORD` | 空 | **不设则跳过第⑦步** |
| `REDIS_CONTAINER` | 空 | 已存在的 Redis 容器名（优先用 `docker exec`） |
| `REDIS_ADDR` / `REDIS_IMAGE` | `127.0.0.1:6379` / `redis:8.8.0` | 未指定容器时用一次性容器执行 `redis-cli` |
| `LOGIN_USER` / `LOGIN_PASSWORD` | `admin` / `admin123` | 登录验证用的账号 |

## 5. 五个阶段到底做了什么

| 阶段 | 本机/服务器 | 具体动作 |
|---|---|---|
| `build` | 本机 | 后端：`mvn -B -q -DskipTests -pl :spzx-xxx -am package -Dnacos.addr=...`；前端：`cd spzx-ui && npm run build:prod` → `dist/` |
| `pack` | 本机→服务器 | 生成 `Dockerfile`（后端 `eclipse-temurin:21-jre`；前端 `nginx:alpine`）、`nginx.conf`、`docker-compose.yml`；上传 jar（auth 91MB / gateway 94MB / system 93MB / product 108MB）或前端 tar.gz（约 2.4MB）。**上传 compose 前会把服务器上已有的 compose 备份成 `docker-compose.yml.bak.<时间戳>`**；后端 jar 会预检内部 Nacos 地址 |
| `image` | 服务器 | `docker compose build spzx-xxx` |
| `up` | 服务器 | `docker compose up -d spzx-xxx`（配置有变化时自动重建该容器） |
| `verify` | 两边 | 见 3.9 的 ①~⑦ |

## 7. 常见问题排查

### 7.1 `Bind for 0.0.0.0:80 failed: port is already allocated`
80 被别的容器占了。**最常见**：网关还是老配置（占着 `80:8080`），而前端要用 80。解决：
```bash
./docker/remote-deploy.sh up gateway ui      # 网关按新 compose 重建（只留 19080），ui 拿 80
```
或者给前端换端口（不用动网关）：
```bash
UI_PUBLISH="8081:80" ./docker/remote-deploy.sh all ui
```
> `UI_PUBLISH` 必须在 `pack` 时就带上，因为 compose 文件是 pack 阶段生成的。

### 7.2 报 `unbound variable`（脚本内部）
历史 bug，已修（UTF-8 locale 下 `$VAR` 紧跟全角字符会被当成变量名）。若再遇到，说明有新代码违反了这条约定——脚本头部已写明"消息里变量一律写 `${VAR}`"。

### 7.3 `jar 内 Nacos 地址 = 'xxx'，预期 'yyy'`
jar 是用别的 `nacos.addr` 打的。要么按预期重新 `build`，要么用 `NACOS_ADDR=<jar 里的地址>` 重跑。改机部署时尤其注意（见 3.10）。

### 7.4 容器起来了，但 Nacos 里没注册
```bash
./docker/remote-deploy.sh logs auth | grep -i -E "nacos|error" | tail -30
```
常见原因：`NACOS_ADDR` 不通（目标机防火墙/Nacos 未启动）、Nacos 客户端版本与服务器不兼容。

### 7.5 前端页面 502 / `/prod-api/...` 502
前端 nginx 用 `resolver` + 变量在**请求时**解析 `spzx-gateway`，所以网关没起来时 nginx 仍能启动，但请求会 502。先确认网关在跑：
```bash
./docker/remote-deploy.sh status gateway
./docker/remote-deploy.sh logs gateway | tail -30
```

### 7.6 服务器内存不够（3.7G 的机器尤其注意）
```bash
./docker/remote-deploy.sh status          # 看各容器内存占用
```
组合拳：
```bash
# 压小堆 + 只部署需要的服务
SYSTEM_HEAP=256m AUTH_HEAP=160m GATEWAY_HEAP=160m ./docker/remote-deploy.sh all auth system
# 给某服务加硬上限（被 OOM 时只杀它自己）
PRODUCT_MEM=640m ./docker/remote-deploy.sh up product
# 暂时停掉不用的服务
./docker/remote-deploy.sh stop system
```
实测参考（150.158.27.19，默认参数 + CDS）：gateway ≈ 343MB、auth ≈ 397MB、system ≈ 419MB、ui ≈ 4.6MB。

### 7.7 product 启动后日志一直刷 RabbitMQ 连接错误
`spzx-product-dev.yml` 里配了 `150.158.27.19:5672`，但该服务器没有 RabbitMQ。服务仍能启动并注册，只是库存解锁/扣减消息不可用。要完整可用：
```bash
ssh root@150.158.27.19 docker run -d --name rabbitmq --restart unless-stopped \
  -p 5672:5672 -p 15672:15672 rabbitmq:3-management
```

### 7.8 我要看某个服务到底怎么样
```bash
./docker/remote-deploy.sh status
./docker/remote-deploy.sh logs <服务名>
ssh root@<服务器IP> docker exec -it spzx-auth sh      # 进容器
```

## 8. 命令示例速查（直接复制）

```bash
# ---- 部署 ----
./docker/remote-deploy.sh                                   # 全部服务全流程
./docker/remote-deploy.sh all ui                            # 只发前端
./docker/remote-deploy.sh all gateway auth system            # 只发三个后端
./docker/remote-deploy.sh all product                        # 只发商品服务
ONLY="ui auth" ./docker/remote-deploy.sh all                 # 发两个
TAG=v1.0 ./docker/remote-deploy.sh all gateway auth system    # 版本化

# ---- 省流量的更新 ----
SKIP_JARS=1 PRODUCT_HEAP=320m ./docker/remote-deploy.sh pack product
SKIP_MAVEN=1 ./docker/remote-deploy.sh all auth              # 用已有 jar 重发

# ---- 运维 ----
./docker/remote-deploy.sh status
./docker/remote-deploy.sh logs ui -f
./docker/remote-deploy.sh restart gateway
./docker/remote-deploy.sh stop system
./docker/remote-deploy.sh down ui
./docker/remote-deploy.sh clean

# ---- 验证 ----
./docker/remote-deploy.sh verify
./docker/remote-deploy.sh verify gateway ui
REDIS_CONTAINER=1Panel-redis-xmqE REDIS_PASSWORD=940101zx ./docker/remote-deploy.sh verify

# ---- 换机 ----
SSH_HOST=root@10.0.0.9 HOST_IP=10.0.0.9 NACOS_ADDR=10.0.0.9:8848 \
  ./docker/remote-deploy.sh all gateway auth system ui
```
